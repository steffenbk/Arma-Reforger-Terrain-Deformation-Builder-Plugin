## What the code does today (VERIFIED-CODE 2026-10-17)
- Rut op (kind 4): server MUD_WorldGround (~:1214) gives each wheel step = m_fRutStep (prefab 0.08) and cap =
  min(m_fRutBaseDepth + mass t x m_fRutDepthPerTon, m_fRutMaxDepth) -> MUD_VoxelProbe.RutWheel (:918) -> DoRutOp
  (:2818): op.m_fDepth = step, op.m_fB = cap, m_sPlan = segments in cm. So depth is ALREADY load-based by vehicle
  mass; the step per pass is fixed.
- CarveFloor (:4120): profile fall = 1 - k^2 over RUT_R 0.5; per floor sample floorY = surf - step x fall, not under
  undug - cap x fall, not under undug - FLOOR, rounded to cm (J2); only ever lowers (min); surf = the rut so far.
  Hard / kept samples skipped. Writes are independent per sample (the `foreach best` order does not matter today).
- Floor storage: MUD_RutTile.m_aFloor[256] world y, FLOOR_NONE = none (:146). One value per sample - nothing can go
  UP: patches draw y = min(smooth, floor) in 4 places (MUD_WorldGround ~:6089 mesh, :6213 collider, :6388 / :6542
  band mesh / collider), edge-locked.
- J2 snapshot: TileText (:1574) sends m_aFloor only, as cm deltas + "n<k>" none runs. Any new per-sample value must
  join this format, LoadSnap (:1797) and the TEST_KIT SnapSelfTest (:1885).
- Rut cells (RUT_CELLS / rut layer): NOT BUILT (no RUT_CELLS in Scripts; gated on PERF numbers we don't have). So
  "drawn on the rut layer" and ClutterOccluder on its prefab are not available in Build 3.
- Patch collider: already one trimesh geom per material slot (MUD_WorldGround ~:6238 `p.m_aMats[k]`, cells carry a
  slot in m_aCell). A wheel reads the hit geom's gamemat (IDA answers 5 / 6). So a "rut mud" gamemat can be an extra
  slot for 2 m cells with a deep rut - no rut layer needed.
- Look channel: op 6 / RUT_LOOK exists for bricks only and is off (RUT_LOOK false, :255). No texture drag, no slump,
  no fresh-mud material on patches.

- Vehicle mud / particles: no SetWheelMud / SetBodyMud / mud effect calls in our scripts. 0-WB #6 (rain) never run.

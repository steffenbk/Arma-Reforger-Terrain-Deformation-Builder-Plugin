# Mud lab: one switcher + a probe field, many ways to deform, one DS session per build (plan, 2026-10-20, v3)

v3 (2026-10-20, after research/2026-10-20-mud-sheet-deep-dive.md): sheet local = the DEPOSIT BAND (thickness from distance to touched cells, no tile-side fade, untouched ground has no tile = no pop), compact far data, sync-lite remote stamps, cost levers L1-L9; lane S2 dropped, R2 demoted.

v2 (user 2026-10-20): "we don't care about mud spray or mud on truck, only the deformation. What if we test more like
probing tests too with different ways to deform". Spray, muddy vehicles, decals, clods, tyre sink and mud drag are
moved to Parked ideas. The lab is now about deformation only: how the mud changes shape, and how that shape is drawn.

Goal: get as close to the MudRunner mud feel as we can. It does not have to match one to one. The old MudSheet (v206,
parked) looked best ("how it deformed and flowy it was"). Its blockers were per-frame script cost and scaling to the
whole map. D1 (overlay) and D2 (pressed lift) failed on the DS (results/2026-10-20-mud-two-designs-ds.md). Why:
research/2026-10-20-mud-look.md (D1 had no soft layer, D2 had no simulation). The useful thing from that round was the
numpad 3 switcher, so it becomes permanent.

## 0. Hard rules
- **The voxel ruts are off limits.** That covers rut ops, the rut field, wear (RUT WEAR v234), look ruts, the patch
  meshes and colliders, and the op format. Lab code may READ rut data and draw its own meshes. Only D2 is an exception
  the user allowed, behind its own switch. Any probe that would write into the patch drawing (R7 below) needs the
  user's OK first.
- **Client look only.** Lab code never writes J2, ops, snapshots or anything the DS reads, and nothing in it runs on a
  DS.
- **Default off.** Off must behave exactly like today; check every touched gate by grep.
- **Tests follow the CLAUDE.md TESTING RULES.** One combined session per build. Workbench is for function and look only,
  never for ms or fps. Numbers come from the DS client (or the standalone game), with at least 6 runs per row.
- **Feature freeze still applies.** Lab work IS the mud lane. Ideas outside this plan go to Parked ideas.

## 1. Two kinds of test
1. **Surface modes, in the world (numpad 3).** A method runs on the real ground while you drive: the full feel, MP,
   several trucks. This is costly to build, so only methods that won the probe field get here.
2. **The probe field, side by side (new).** A row of lanes on flat holed grass. Each lane is one deformation method,
   and every lane gets the SAME recorded wheel input. One launch shows every method at once, with per-lane cost. Lanes
   are client-only meshes: no rut ops and no felt ruts, look and cost only.

### 1.1 Wheel track recorder and replay
- **Record.** Every `MUD_MudSheet.Stamp(lp, cp, speed, time, vehId, half)` input that `Wheels()`
  (MUD_MudSheet.c:4067) would make goes to `$profile:MUD_wheeltrack_<date>.csv`, one row per stamp: t, veh, wheel,
  lp xyz, cp xyz, speed, half. Recording works with the sheet off: the same contact reads, no stamping. Record the
  robot circle once, and a straight 1 / 2 / 4-pass line plus a crossing.
- **Replay.** A probe key plays one file into every lane at the same time. Each lane gets the track moved to its own
  origin (lane width 12 m, with 2 m gaps), and the heights are re-read from the drawn ground at the lane (read only).
  Replay speed 1x, plus a "stamp all at once" option for cost-only runs.
- **Per-lane meters** in the 10 s line (sec 2): stamp ms, rule ms (slump and so on), build ms, builds, verts, entities.

### 1.2 Lanes = renderer x rule
A lane is a pair: a RENDERER (how the deformed shape becomes something on screen) and a RULE (how the mud moves). The
first lanes keep the sheet's renderer and vary the rule. Later lanes keep the sheet's rule (S1) and vary the renderer.
That way every comparison changes one thing.

**Rules** (deformation maths; all run on the sheet's 0.15 m field unless noted):
| id | rule | what it should add | notes |
|---|---|---|---|
| S1 | today's sheet: BOX + SOFT + GRADUAL stamp, ridges, bow wave, drag + LimitDrag, slump 0.25 x 3 at 10 Hz | the reference look | MUD_MudSheet as is |
| ~~S2~~ | DROPPED: volume-kept berms were the sheet's v1 (checkpoint v047) and came out 2-3 cm high, invisible; MudRunner keeps no volume either (PUSH = a max shape) | - | deep dive sec 5 |
| S3 | slow settle: after the wheel leaves, the groove walls sag and the ridges spread over 5-20 s | the "flowy" after-motion | ages per cell; runs at 2-5 Hz only on settling cells |
| S4 | speed and slip: a slow, heavy wheel sinks deeper; a spinning wheel digs and throws a lump behind | bogging look | needs wheel slip: use it only if the API dump has a slip read, else skip S4 |
| S5 | wet / dry presets: thickness, SOFT, slump and settle together (wet = deeper first pass, more flow) | one knob for "how muddy" | presets over S1-S3 |
| S6 | one-pass slump 0.6 (offline ≈ 3 passes at 0.25) | S1's look for less rule cost | results/2026-10-19-sheet-sync-maths-offline.md |

**Renderers** (how the shape is drawn):
| id | renderer | expected cost and look | known risks (research refs) |
|---|---|---|---|
| R1 | sheet script-mesh tiles, 3 m at 0.15 m | the reference; ~0.55-0.9 ms per tile build | cost grows with busy trucks |
| R2 | R1 with 1.5 m live tiles (DEMOTED: one wheel changes ~1.4 x 0.6-1.1 m per upload, so counting skirts 1.5 m tiles rebuild MORE vertices at 10 m/s; deep dive sec 1.3) | probably no gain | more entities and skirts |
| R3 | coarse 0.30 m grid + parallax mud material for fine detail | ~4x cheaper builds | ridges lose sharpness (~10 %), parallax fails at low view angles (sec 3.6) |
| R4 | rut ribbon (NEW): a strip mesh per wheel track, extruded along the path with a cross-section (groove, walls, ridges) from the rule's depth; only the last chunk rebuilds | tiny builds (~10 verts per 0.15 m step) | crossings overlap (z-fight), no flow between tracks, no bow wave spread |
| R5 | premade rut pieces (.xob, 1.5 m) placed along the track; 2-3 variants (fresh / pressed / deep) swapped per pass | zero per-frame cost when static; authored normals, vertex alpha, LODs | no accumulation in between variants, crossings overlap, a "sticker" look risk; needs Blender assets (sec 3.4, 12, 15.2 design A) |
| R6 | skinned live tile moved by bones (1.5 m, 11 x 11 bones) and baked to a script mesh when the wheel leaves | no mesh upload under the wheel | per-frame bone palette for every drawn skinned tile (live only), no texture drag, bounds need a `BoundingBox` override; needs a Blender asset (sec 15.3, 15.8, 15.9) |
| R7 | hybrid bake: sheet tiles only while mud moves, then the final shape is baked into the patch and the tile is freed | memory and stored cost fixed | writes into the patch drawing: needs the user's OK; one pop per tile at the hand-off (sec 3.7) |
Dead ends, so no lanes: TrackDecal (terrain only), stored skinned tiles (per-frame palette), ProcAnim on every piece,
merged tiles, in-place vertex updates (sec 5, 15.1, 15.8).

### 1.4 Engine-native track (the engine moves the shape, script only feeds it)
Research: research/2026-10-20-engine-native-deformation.md. These are standalone probes first: yes / no plus a
screenshot each, one WB launch. Only the ones that pass get a lane in the probe field.
| id | idea | engine part [API] | needs |
|---|---|---|---|
| N1 | wheel-attached groove + bow-wave mesh, pieces dropped behind it (no live rebuild under the eye) | `AddChild` to a non-spinning node, ProcAnim signal / `SetMorphState` | a groove mesh |
| N2 | ruts painted as 2D strokes into a render target that the mud material reads (wet mask, normal, height) | `RTTextureWidget.SetRenderTarget` -> `$rendertarget`, `CanvasWidget` line / polygon / trimesh commands, `SetRenderView` + orthographic camera | nothing |
| N3 | shell layers alpha-cut by the N2 texture, giving fake volume with a silhouette | N2 + alpha-tested emats | N2 passing |
| N4 | physics mud mat: gravity-off, damped bodies on vertical limit joints, pushed by client-only wheel proxies (plastic, stays pressed) | `EnableGravity`, `SetDamping`, `Physics6DOF(Spring)Joint`, `SetActive` | nothing (boxes) |
| N5 | the same mat as a real ragdoll: the engine drives the bones of a skinned grid | `PhysicsRagdoll.CreateRagdoll` | a skinned grid .xob + ragdoll definition (format from the user's "Euphoria ragdoll" addon) |
| N6 | granular mud: hundreds of small bodies that pile into ridges and bow waves | rigid bodies | look reference only |
Not there: soft body / cloth (no script API), runtime terrain edits, custom shaders. "Volumetric smoke" is particles,
which cannot hold a shape.

### 1.3 The lab framework (both kinds)
New file `Scripts/Game/Mud/MUD_MudLab.c`. It is ticked from the existing call site `MUD_WorldGround.c:1086` (today
`MUD_MudOverlay.Tick(m_fTime)`).
- **Surface modes** (one at a time, numpad 3): off -> sheet local presets -> D2 presets -> D1 presets (until D1 is
  archived) -> off.
- **Probe field** (Left Ctrl + numpad 3, TEST_KIT only; numpad 1-9 are all taken):
  - the first press places the field in front of the player (the lanes set in code, with labels drawn above each lane);
  - the next press starts replay of the selected track;
  - the press after that steps to the next track file;
  - a long hold (1 s) removes the field.
- **Label.** DbgUI top left, as today, plus the field state: track, time, lanes.
- **Logs:**
  - on every switch: `MUD lab: surface <name> preset <p> | field <on/off> track <file> | (key|new play)`;
  - every 10 s for the surface: `MUD lab 10s: surface <name>/<p> | fps avg <f> min <f> | MUD ms <f> | mode ms <f> | tiles <n> built <n> kept <n> | <extras>`;
  - every 10 s per lane: `MUD lab lane <id> <R>x<S>: stamp ms <f> rule ms <f> build ms <f> builds <n> verts <n> ents <n>`.
  - MUD ms comes from the existing frame meter or FrameLog (the same number the 2026-10-20 results used).
- **New play** resets everything to off.

## 2. Surface mode 1 - sheet local (stage 1)
The old MudSheet in the world: client-only and decoupled, with all seven look parts (research/2026-10-20-mud-look.md
sec 2).
- **Switching.** `MUD_MudSheet.ENABLED` becomes a runtime `static bool` set by the lab (today it is a `static const`).
  On Exit, every sheet tile entity and all sheet data are freed. On Enter, the sheet starts from fresh state.
- **Couplings off.** In sheet local, every rut file must behave as if the sheet were off:
  - `SYNC`, `LAZY_RUT_MESH`, `MUD_LookRuts.SHEET_LOOK` and `SHEET_SKIP` are set to false (`ONE_GRID` is false
    already).
  - `MUD_MudZoneEntity.SheetCovers` (MUD_MudZone.c:62) returns false unless `ENABLED && SYNC`. This covers the
    remaining callers: MUD_LookRuts 236 / 368 / 512 / 613 and MUD_VoxelProbe 1433 / 3980 / 8445.
  - The local AI lists every reference from a rut file to the sheet, with the gate that keeps it inert.
- **Where it draws: the DEPOSIT BAND** (research/2026-10-20-mud-sheet-deep-dive.md sec 3; v2 of this plan had tile-side
  fades and a BORN rule, but the deep dive showed a born tile with a THICK baseline is a 3 m slab, 16 cm high, appearing
  at once).
  - Thickness per vertex = THICK x band(dist to the nearest touched cell): 1 within BAND_IN (0.4 m), a sine falloff to 0
    at BAND_IN + BAND_FADE (0.8 m), and ~1 cm UNDER the drawn ground at 0, so the edge comes out from under the patch.
    It is computed in world cells across tile borders, like the taper field. There is no tile-side EDGE fade, and
    `HasTile` plays no part.
  - Untouched cells have no tile at all. A tile is born when a stamp touches it; a band change near a tile side marks
    the neighbour.
  - `Wheels()` stamps where `ZoneAtWorld` is true; in local mode that means "holed offroad ground", so no zone entity is
    needed.
  - No zone pre-build, no RADIUS sweep. The live window draws and freezes ONLY born slots. Today it draws and freezes
    all 16 (Follow 1077, Upload 5248).
  - `MudAt` / `MUD_MudSync.Get` default: unborn cells = 0, not THICK. Callers: MUD_TrenchGhost 87,
    MUD_VehicleAccess 138.
  - No patch lift, no LIFT_BY_DRAWN, no LAZY_RUT_MESH in this mode: the patch draws untouched ground exactly as today.
  - Far tiles: data only, compact (1 byte per value, ~1.8 KB per tile), up to TILE_DATA_CAP (20,000, ~36 MB). Meshes
    within a fixed 60-80 m radius, nearest-ahead first, ~2 ms/frame budget. SPEED_RADIUS off, LOD double build off. A
    far ring past ~40 m is built once at 11 x 11.
  - Never build a slot until all its cells are traced. Finish eases in `Freeze`. Give MAT_TOP the 64 m chunk UV frame
    (as voxel tops do), so the texture keeps its scale at the band edge.
- **Several vehicles (MP).**
  - Own truck: live 10 Hz window as today.
  - Remote trucks, sync-lite: a read-only listener on the rut ops the client receives (`MUD_MudSheet.FloorChanged`
    or the op stream) stamps their segments into the tile data with the same Stamp maths. There is no hash, quantise,
    snapshot or DS work. It is close on every client, not identical, and appears at the op pace (~0.75 s behind the
    truck). The client's own ops are skipped by vehicle id.
  - Optional later: local stamps from proxy wheel contacts, if the probe shows that clients get them.
- **Cost levers** (deep dive sec 2: L1-L9, look-neutral). Build L1 (no blanket slot dirty on shift), L2 (LimitDrag
  once per upload over stamped cells + 1), L3 (slump only on changed cells, one pass at 0.6), L6 (EaseTick at upload
  rate) and L8 (vehicle loops) with sheet local. L4 (build rewrite with static holders) and L5 (compare to last build)
  come in stage 2. First a 10 s 'builds by reason' log line, plus "would skip: max change < 3 mm".
- **Holes.**
  - Rebuild crater and dig tiles in the blast frame, not via `UploadPick`.
  - The `DigNow` stored path (~3446) also queues its taper neighbours.
- **Base height.** Keep v206's ground read. Check by eye that the tyre sits in the groove.
- **Presets:** BAND_IN 0.4 / 0.8 x BAND_FADE 0.8 / 1.2 (THICK stays 0.15).
- **Budget:** at most ~3 ms/frame over 'off' with one truck. **Kill** if it is over budget after the perf work, or if it
  does not look like the old sheet.
- **Known limits:**
  - each client's mud is close, not identical;
  - a late joiner sees only voxel ruts on ground driven before they joined (unless a later stage stamps those tiles
    from the rut field);
  - an area is mud only after someone drives it. An optional pre-touched mask (the old zone boxes) can make a field
    muddy from the start, built once.

When a probe lane beats S1 x R1, its rule or renderer is swapped into sheet local as a new preset. That is how the
probe field feeds the world mode.

## 4. DS session template (stage 1)
DS + PeerPlugin1, a fresh truck after start, at least 6 runs per row.
1. off: baseline while DRIVING (robot circle on grass).
2. Sheet local, each preset (robot circle): MUD ms, mode ms, sheet meters, builds by reason, tiles, data KB; then levers L1 / L2 / L3 / L6 off vs on.
   By eye: does it deform and flow like the old sheet; no pop when a band is born (look from 5 m); no step at the band edge; grass on the band; does the tyre sit in
   the groove.
3. D2 preset 4: the same numbers.
4. Crater + trench in a sheet area; a second truck ~40 m away; a late joiner.
5. Probe field: replay the robot track into all lanes. Per-lane ms (6 replays), then by eye from 2 / 20 / 60 m per
   lane. Rank the lanes: look 1-5 and ms.

Results go to `results/2026-10-2x-mud-lab-stage1-ds.md`: one table for the surface rows and one for the lanes.

## 5. Feasibility (the honest version)
- **Feasible:** the old sheet's deformation around the action, wherever wheels go near the camera, kept along the
  tracks.
- **Whole map:** only in the sparse sense, which is what MudRunner does too (dense mud only where it exists, simulation
  near the player). A sheet over all ~5.6 km² of holed ground cannot be built: about 622,600 tiles, 37-47 GB, and
  6-30 min of builds.
- **Hard limits:**
  - script-only mesh builds (~1-2 ms/frame per live truck before perf work);
  - no shaders, no vertex colours on script meshes, one UV set, one mesh LOD;
  - every client draws its own mud: close, not identical.
- **Where the probe field can still win:**
  - R3 cuts build cost with the same rule; R2 (1.5 m tiles) likely does not;
  - R4 / R5 are cheap but lose flow at crossings;
  - S3 (slow settle) is the likeliest to add the "flowy" feel. It is a rule change, so it costs script time, not builds.
